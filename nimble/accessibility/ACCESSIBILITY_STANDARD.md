# Nimble™ Accessibility Standard

Accessibility is a foundational engine of Nimble™, not a compliance
overlay.

## Required Standards

All primary interactions must support keyboard operation.

Focus must always be visible.

Focus order must reflect visual and logical order.

Motion must support reduced-motion preferences.

Color must never be the sole carrier of meaning.

Status changes must be available to assistive technology.

Interactive elements must expose clear names, roles, states,
and relationships.

Dragging must have an alternative interaction when practical.

Resizable and dockable surfaces must be operable without precision
pointer input.

Errors must identify:

- what failed,
- where it failed,
- why it failed when known,
- and how to recover.

## Motion

Reduced-motion mode must preserve:

- hierarchy,
- causality,
- state change,
- progress,
- and completion.

Meaning may not disappear when animation is disabled.

## Principle X

Accessibility requires truthful presentation.

The platform must not conceal uncertainty, incomplete state,
validation errors, blocked actions, or unavailable capabilities
from assistive technology users.
