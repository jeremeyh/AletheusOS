# Nimble™ Motion Constitution

Motion is a communication system.

It must reveal state, causality, hierarchy, continuity, progress,
confidence, and reversibility.

## Motion Must

- clarify where an object came from,
- clarify where it moved,
- reveal relationships,
- communicate state transitions,
- preserve spatial continuity,
- indicate active system behavior,
- support direct manipulation,
- remain interruptible,
- remain reversible where the action is reversible,
- respect reduced-motion preferences,
- degrade gracefully,
- and remain within defined performance budgets.

## Motion Must Not

- conceal latency,
- fake progress,
- block user control,
- create unnecessary delay,
- obscure system state,
- distract from critical information,
- induce disorientation,
- or exist solely as decoration.

## Categories

### Micro Motion

Hover, focus, press, selection, validation, and state confirmation.

### Structural Motion

Panel opening, docking, resizing, expansion, collapse, navigation,
workspace reflow, and shared-layout transitions.

### System Motion

Background processing, agent activity, synchronization, streaming,
runtime state, confidence shifts, and live topology changes.

### Narrative Motion

Guided explanation, decision trace, workflow traversal,
provenance exploration, and temporal change.

### Ambient Motion

Subtle environmental activity that conveys system vitality without
competing with primary content.

## Accessibility

Reduced-motion mode must preserve meaning without relying on movement.

Animations must never be the sole carrier of state.
