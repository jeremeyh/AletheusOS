# Genesis 39.1 — Canonical Cleanup and Refinement

Genesis 39.1 removes overlapping Genesis 38 component paths and establishes
one authoritative implementation for the LIGHTS™ / SIGHT™ experience.

## Canonical implementation

- `AxiomCard.tsx` — living topology-aware instrument surface
- `LIGHTSField.tsx` — WebGL2 LIGHTS field mount
- `FounderObservatory.tsx` — constitutionally isolated root observability plane
- `lights-engine.ts` — liquid-metal field and Principle X emergence
- `information-physics.ts` — density, phase, resonance, mass, and MQ equations
- `sight-haptics.ts` — bounded perceptual feedback
- `types.ts` — canonical shared telemetry, phase, risk, and instrument contracts

## Removed legacy paths

- `AdaptiveField.tsx`
- `InstrumentCard.tsx`

These components belonged to the pre-LIGHTS Genesis 38 implementation and
caused phase-name and contract drift after Genesis 39.0 was installed.

## Canonical phase vocabulary

1. Nebular
2. Fluid Reactive
3. Quasi-Penrose
4. Crystalline Solid

`Quasi-Crystalline` is deprecated and prohibited in active frontend source.

## Cleanup law

A release installer must remove explicitly superseded files before copying
canonical replacements. Overlay-only installation is prohibited when stale
source can continue participating in TypeScript compilation.

## Validation gates

Genesis 39.1 fails installation when:

- a legacy component remains,
- a forbidden phase term remains in active source,
- a legacy component is imported,
- TypeScript validation fails,
- the production Vite build fails,
- canonical source inventory tests fail.
